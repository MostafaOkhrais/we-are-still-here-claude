Deployment - Cloudflare Pages + D1 - wearestillhere.uk
=======================================================

Architecture (no external backend)
  public/      the published site (HTML, js, css, assets, _headers, _routes.json)
  functions/   the API (Cloudflare Pages Functions): /api/*   -> contact form, newsletter, news, admin
  migrations/  D1 (SQLite) schema
  scripts/     create-admin.mjs
  src/         Tailwind source and source fonts (not published)
Only public/ is served. functions/ runs as code.

What the backend does
  - Contact form -> stored in D1, optional email notification to you (NOTIFY_EMAIL)
  - Newsletter -> double opt-in (confirmation link), welcome email, one-click unsubscribe,
    List-Unsubscribe headers, send campaigns from the admin page
  - News/events -> managed in /admin, shown on /news
  - Admin -> own sign-in (PBKDF2 passwords, HttpOnly SameSite=Strict session cookie, CSRF checks,
    failed-login throttling). Add Cloudflare Access on top (step E) for a second lock.
  - Abuse protection: per-IP rate limits (D1), honeypot + timing check, link limit, body limits.
  IP_SALT is required: without it the contact form, newsletter and admin sign-in answer with an error
  (the server refuses to hash visitor IPs with a public default).
  Without RESEND_API_KEY the site still works, but the newsletter form answers "try again later"
  (every address must confirm by email), contact messages are only stored, and the "send newsletter"
  button is disabled. Set RESEND_API_KEY before announcing the newsletter.
  Campaigns are limited to 2000 subscribers per send (use the language audience to split a larger list),
  and the same subject and text cannot be sent twice within 10 minutes.

A) One-time Cloudflare setup (dashboard / terminal)
   0. Node 20 is pinned in .node-version (Cloudflare Pages reads it).
   1. npm install
   2. npx wrangler login
   3. npx wrangler d1 create wash-db
      -> copy the printed database_id into wrangler.toml (database_id = "...")
   4. npm run db:migrate:remote           (creates the tables in production)
   5. npm run admin:create -- --remote    (prompts for the admin email and a 12+ character password;
                                            run again any time to reset a password)

B) Push to GitHub
   1. npm run build                       (writes public/css/tailwind.css, the Arabic pages public/ar/*.html and
                                           public/sitemap.xml; commit them. Edit the English pages in public/,
                                           never public/ar/, then run the build again.)
      Every page has an English URL (/about) and an Arabic URL (/ar/about) with hreflang links; the AR/EN
      button opens the other one. Newsletter links in emails open a page with a confirm button.
   2. git add -A ; git status             (.dev.vars, node_modules, .wrangler must NOT appear)
   3. git commit ; git push origin main

C) Pages project
   1. Workers & Pages > Create > Pages > Connect to Git > this repository
   2. Framework preset: None | Build command: npm run build | Build output directory: public
   3. The D1 database comes from wrangler.toml (binding DB, once you pasted the real database_id in step A3).
      Pages then shows it as read-only in Settings > Bindings. Do not add a second binding by hand.
   4. Settings > Variables and Secrets > Production, add these as type "Secret" (Encrypt):
        IP_SALT          long random string (required; the site refuses to run without it). Create one with:
                         node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
        SITE_URL         https://wearestillhere.uk       (used in email links)
        RESEND_API_KEY   from https://resend.com        [email; without it the newsletter form says "try again later"]
      EMAIL_FROM and NOTIFY_EMAIL are public settings kept in wrangler.toml [vars]; edit them there.
      CONTACT_RECEIPT = "1" in wrangler.toml [vars] turns on the automatic "we received your message" reply.
      Secrets are used by the NEXT deployment: after adding them press Deployments > Retry deployment (or push).
   5. Deploy, then test on the *.pages.dev address first (checklist G).

   Mailbox for info@wearestillhere.uk (shown on the site, used for NOTIFY_EMAIL):
   the address must exist before launch. Free option: Cloudflare dashboard > Email > Email Routing >
   enable it for wearestillhere.uk, add the custom address info@ and forward it to your own inbox
   (verify the destination address when Cloudflare emails you). Replies still need a mail client
   that can send as info@ (or reply from your own inbox).

   Email setup (Resend): add the domain wearestillhere.uk in Resend, add the DNS records it shows
   (SPF/DKIM) in Cloudflare DNS, wait until it says Verified. EMAIL_FROM must use that domain.

D) Domain
   1. Custom domains > add wearestillhere.uk and www.wearestillhere.uk
   2. Rules > Redirect Rules: www.wearestillhere.uk/* -> https://wearestillhere.uk/${1} (301)
   3. SSL/TLS: Full (strict); Always Use HTTPS: On

E) Extra protection
   1. Zero Trust > Access > Applications > Self-hosted: wearestillhere.uk/admin  -> your email only
      (also add /api/admin/* to the same application)
   2. Security > WAF > Rate limiting rules (extra layer on top of the built-in limits):
        URI path starts with /api/admin/login     10 requests / 10 min / IP -> Block
        URI path in /api/contact, /api/newsletter  20 requests / hour / IP -> Block
   3. Security > Bots: Bot Fight Mode On
   4. Speed > Optimization: Rocket Loader OFF (it injects scripts and the strict Content-Security-Policy blocks them).
      Scrape Shield: Email Address Obfuscation OFF (the site shows info@wearestillhere.uk as plain text).
      Do not enable Web Analytics for this project (the privacy policy says there is no analytics).
   5. SSL/TLS > Edge Certificates: Minimum TLS 1.2, Automatic HTTPS Rewrites On. DNS > Settings: DNSSEC On
      (then add the DS record at the .uk registrar).
   6. Pages project > Settings > General > Access policy: protect preview deployments (*.pages.dev) so test
      versions are not public or indexed.
   7. Turn on two-step verification for the Cloudflare, GitHub, Resend and Google accounts.
   8. Email routing warning: before enabling Email Routing check DNS > Records for existing MX records. If the
      domain already has mailboxes (Google Workspace, Zoho...), do NOT enable it (it replaces the MX records);
      create the info@ address inside that mail service instead.

F) Search engines (do after the domain is live)
   1. Google Search Console > Add property > "Domain" wearestillhere.uk > add the TXT record it shows in
      Cloudflare DNS. (The site also carries the older HTML-tag verification, so either works.)
   2. Search Console > Sitemaps > submit  https://wearestillhere.uk/sitemap.xml
   3. Search Console > URL inspection > test the home page and request indexing.
   4. Bing Webmaster Tools > import the site from Search Console, or add it and submit the same sitemap.
   5. Social previews: paste https://wearestillhere.uk/ into the Facebook Sharing Debugger and the
      LinkedIn Post Inspector, and press "Scrape again" so they pick up assets/og-image.png.
   6. Old Vercel site (we-are-still-here-ten.vercel.app): add a permanent redirect to the new domain, or
      remove it, so there is no duplicate site.
   7. Structured data: run https://search.google.com/test/rich-results on the home page (Organization).
   SEO already in place: one canonical URL per page, unique titles and descriptions, Open Graph and
   Twitter cards with a 1200x630 image, JSON-LD (Organization, WebSite, BreadcrumbList), sitemap.xml,
   robots.txt (blocks /admin and /api; /subscription stays crawlable so its noindex is read), noindex on admin / 404 / subscription pages,
   favicon + Apple touch icon + web manifest, security.txt.

G) Post-deploy checklist
   - Pages load; English default; AR toggle works
   - Contact form: success message; message appears in /admin; email arrives (if configured)
   - Newsletter: confirmation email arrives, link activates, welcome email, unsubscribe link works
   - /admin: sign in, mark a message read, publish a news post and see it on /news
   - Send a test newsletter to yourself from /admin before sending to subscribers
   - 404 for: /package.json /migrations/0001_init.sql /functions/api/x /src/input.css /wrangler.toml
   - DevTools Console: no CSP errors

Local development
   1. cp .dev.vars.example .dev.vars
   2. npm run db:migrate:local
   3. ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='a-long-password' npm run admin:create
      (or run without the variables to be prompted)
   4. npm run dev        -> http://127.0.0.1:8788   (EMAIL_DRY_RUN=1 prints emails to the console)
   Local data lives in .wrangler/ (git-ignored). Delete that folder to start over.
